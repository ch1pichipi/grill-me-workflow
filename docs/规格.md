# 聊天审核系统 · 规格

验收标准的写法：每一条都能被"跑一下、看一眼"判定真假。带具体数字的例子（如 `L1 第 3 次 → 1d`）是**可执行断言**，不是示意。

上游文档：`docs/设计共识.md`（结论）、`docs/技术选型.md`（理由）、`docs/adr/`（难以逆转的决定）、`GLOSSARY.md`（术语）。

---

## 0. 范围

### 包含

单机演示系统：玩家管理、WebSocket 聊天、审核管线、等级与处置、禁言状态机、语料库管理、agent 变更草案与审批、草稿试跑、修订与回滚、判定留存。

### 非目标

- 登录、鉴权、多用户权限、多实例部署。
- 管理员可编辑惩罚阶梯（只读展示）。
- 多 LLM provider 抽象。
- 数据库迁移脚本（启动时 `CREATE TABLE IF NOT EXISTS`）。
- 审核私聊、审核其他任何非聊天能力、多语言 UI。
- 规则命中后的"人工复核工作流"（只记录复核信号，不做队列与派单）。

---

## 1. 约定

| 项 | 约定 |
| --- | --- |
| 时间 | 服务端一律用 UTC 存储，前端按本地时区显示 |
| 时长档位 | `[1min, 1h, 1d, 3d]`，索引 0–3 |
| severity | 整数 1–5，无小数、无 0 |
| 永久禁言 | `expiresAt` 为 NULL 且在效 |
| 软删除标记 | `deleted_at` 为 NULL 表示未删除 |
| 消息原文上限 | 2000 字符（超出截断并标记 `truncated`） |
| agent 样本数 | 最近 30 条 |

## 2. 领域实体

字段为实现所需的**最小集合**；具体 DDL 属于实现细节。

**玩家 player**：`id`（自增）、`name`（未删除范围内唯一，可改）、`created_at`、`deleted_at`。

**规则 rule**：`id`（语料库内唯一，人可读）、`description`、`view`（`raw` / `acrostic`）、`matcher`（`literal` / `regex`）、`pattern`、`severity`（1–5）、`enabled`、`examples`（至少 1 条）。

**归一化映射 mapping**：`id`、`from`、`to`、`note`。应用顺序按 `from` 长度降序，等长按 `id`。

**消息 message**：`id`、`player_id`、`text`（≤2000）、`normalized_text`、`created_at`、`truncated`。

**判定 judgment**：`id`、`message_id`、`player_id`、`severity`（最终等级）、`is_violation`、`disposition`、`rung`、`duration`、`created_at`，以及命中的**规则快照**（`rule_id`、`severity`、`pattern`、`view`）。

**禁言 mute**：`id`、`player_id`、`started_at`、`expires_at`（NULL = 永久）、`ended_at`、`end_reason`（`expired` / `lifted` / `replaced`）、`lift_note`。

**修订 revision**：`id`、`operations`（JSON）、`snapshot`（JSON，提交后的完整语料库）、`created_at`、`note`。

**变更草案 draft**：**不落库**，只存在于服务端内存，随连接/会话存活。

## 3. 能力与验收标准

### 3.1 玩家管理

- [ ] 管理员可以创建玩家，名字必填；名字在**未删除**玩家范围内唯一，重复创建返回明确错误。
- [ ] 管理员可以改名；改名后历史判定与禁言仍归属于同一玩家。
- [ ] 管理员可以删除玩家：该玩家从玩家列表与切换框消失，其消息、判定、禁言**全部保留**。
- [ ] 删除后可以用**同一名字**创建新玩家，新玩家的 7 天计数与终身计数均为 0，且不继承任何旧记录。
- [ ] 玩家列表每行显示：名字、当前禁言剩余时间（无禁言显示"无"）、7 天违规次数、终身违规次数。

### 3.2 连接与发送

- [ ] WebSocket 是唯一通道；前端不发起任何用于聊天的 HTTP 请求。
- [ ] 前端有一个"当前玩家"选择器，切换后发出的消息归属该玩家；该选择在 UI 上始终可见。
- [ ] 发送成功时前端收到本条的判定结果（命中规则、等级、处置、若禁言则含到期时间）。
- [ ] 玩家处于禁言中时：消息**不入库**、不产生判定、不发送；前端收到拒绝事件并显示剩余时间。
- [ ] 管理员全局消息流面板实时显示**所有**玩家的消息与判定（含被拒绝的消息及其原因）。
- [ ] 禁言生效时，玩家端立即收到事件并显示倒计时。
- [ ] 禁言到期时（无需刷新、无需再发消息），玩家端收到"你可以说话了"事件，输入框恢复可用。

### 3.3 审核管线

- [ ] 归一化按 `from` 长度降序应用。断言：同时存在 `亻尔 → 你` 与 `尔 → 你` 时，输入 `亻尔好` 得到 `你好`（而非 `亻你好`）。
- [ ] `acrostic` 视图按换行 + 中文标点（。！？；，、……）切句，取每段首个非空白字符。断言：`你真傻。今天天气不错。` 的 acrostic 视图为 `你今`；`你真\n是个\n傻逼` 为 `你是傻`。
- [ ] `literal` 匹配是子串匹配；`regex` 匹配在语料库加载时编译，编译失败则整次提交被拒绝（不会出现"半套语料库上线"）。
- [ ] 规则 `enabled = false` 时永不命中。
- [ ] 规则只在与自己 `view` 一致的文本上匹配。
- [ ] 归一化文本与原文一起留存；判定可展示"归一化前 / 归一化后 / 视图文本"三者，用于解释为什么被拦。

### 3.4 等级

- [ ] 单条规则命中：等级 = 该规则 severity。
- [ ] 命中 2 条**不同**规则：等级 = 二者最高值 + 1。
- [ ] 同一条规则在同一条消息里命中多次：**不**加 1（只算一次）。
- [ ] 等级封顶 5。断言：命中 L5 与 L4 两条不同规则，等级为 5 而非 6。
- [ ] 命中条数写入判定，作为复核信号展示，但**不改变**处置。

### 3.5 处置与档位

- [ ] 计算 `rung = clamp(severity + 7天计数 - 2, 0, 3)`，7 天计数**包含本条**。
- [ ] 断言表（severity / 7 天计数含本条 → 时长）：

  | severity | 7 天计数 | 时长 |
  | --- | --- | --- |
  | 1 | 1 | 1min |
  | 1 | 2 | 1h |
  | 1 | 3 | 1d |
  | 1 | 4 | 3d |
  | 1 | 5 | 3d（封顶） |
  | 2 | 1 | 1h |
  | 2 | 2 | 1d |
  | 3 | 1 | 1d |
  | 3 | 2 | 3d |
  | 4 | 1 | 3d |
  | 5 | 1 | 3d |

- [ ] 终身计数 ≥ 5 时施加**永久禁言**，无视档位公式。断言：终身 4 次、7 天内第 1 次、severity 1 → 1min；之后第 5 次违规则永久。
- [ ] 7 天计数只统计 `is_violation` 的判定，且按判定时间滚动计算（30 天前的一次违规不影响今天）。
- [ ] 被拒绝的消息（禁言期间）不产生判定，也不影响任何计数。断言：玩家被禁言 1h，期间尝试发送 50 次，解除后其 7 天计数不变。
- [ ] 前端只读展示当前阶梯（4 档 + 永久），数据来自后端接口而非前端常量。

### 3.6 禁言状态机

- [ ] 玩家至多一条活跃禁言；接口与 UI 都不可能出现两条。
- [ ] 新判定到来时若已有未到期禁言：新禁言时长取 `max(剩余时间, 新时长)`，旧记录以 `end_reason = replaced` 结束，判定流里可见"被替换"。
- [ ] 禁言记录 `expires_at` 为 NULL 表示永久；永久禁言不会自动到期。
- [ ] 到期判定是惰性的：即使进程从未被访问，只要下一次读取时 `now > expires_at`，该禁言即视为已结束（`end_reason = expired`），且不会误报"仍在禁言"。
- [ ] 到期时刻存在主动推送：玩家端在到期那一秒收到"你可以说话了"，不必等自己再发消息。
- [ ] 管理员可以对任意玩家点击"提前解除"：原因**必填**（空原因被拒绝），操作人记录为 `admin`，`end_reason = lifted`。
- [ ] 提前解除后玩家可以立即发送消息，且其禁言记录仍可在历史中查到。

### 3.7 语料库读取

- [ ] 匹配不查数据库：每条消息只读内存快照。
- [ ] 提交修订后，**下一条**消息即按新语料库判定，不存在重载窗口期。
- [ ] 匹配过程中语料库被替换时，不会出现"半新半旧"的匹配结果（单条消息只使用一个快照版本）。

### 3.8 语料库变更与草案

- [ ] 没有任何代码路径允许 agent 直接修改语料库；唯一的写入路径是管理员提交草案（ADR 0002）。
- [ ] 草案是一组结构化操作，每条包含 `op`（add / update / delete）、`target`（rule / mapping）、`before`、`after`、`reason`。
- [ ] 管理员可以逐条勾选、逐条编辑 `after`、提交**子集**；未勾选的条目丢弃且不再出现。
- [ ] 提交前逐条校验，失败项标红且不可勾选，其余可正常提交。校验项：
  - [ ] severity 为 1–5 的整数
  - [ ] `regex` 规则的正则必须编译通过
  - [ ] `literal` 规则的 pattern 非空；映射的 `from` 与 `to` 均非空
  - [ ] 规则 id 不得与现有规则冲突（add），update / delete 的目标必须存在
  - [ ] **规则必须能命中自己的 `examples` 中至少一条**（用服务端真实管线验证，不用字符串相等猜测）
- [ ] 未配置 `AGENT_API_KEY` 时，"使用 agent 变更语料库"按钮禁用并给出提示；其余功能完全可用，管理员可手工添加规则与映射。
- [ ] 勾选"附带最近消息样本"时才把最近 30 条消息及其判定传给模型；未勾选时不传任何消息内容。
- [ ] 草案中每条建议标注它基于哪几条样本（未附带样本时标注"无样本依据"）。
- [ ] 模型返回非法结构（缺 severity、非法 JSON）时不产生草案，显示明确错误，语料库不变。

### 3.9 修订与回滚

- [ ] 每次提交产生一条修订，包含本次操作列表与提交后的完整语料库快照。
- [ ] 修订列表可查看每次提交的时间、操作摘要、以及前后差异。
- [ ] 可以把任意历史修订的语料库**作为新的一次修订**提交回去；历史修订不被删除或改写。
- [ ] 回滚同样是一条需要"原因"的修订记录。

### 3.10 试跑

- [ ] 试跑使用**草稿状态**的语料库（含草稿中新增/修改的规则与映射），不是已提交的版本。
- [ ] 试跑显示：命中规则（含规则 id 与 severity）、最终等级、7 天计数、档位、会施加的时长。
- [ ] 试跑**不写库**：不产生消息、不产生判定、不改变任何玩家的计数与禁言。
- [ ] 试跑输入可以手动粘贴，也可以从历史消息里选一条。

### 3.11 留存与审计

- [ ] 判定保存消息原文（≤2000 字，超出置 `truncated`）、归一化文本、以及命中规则快照（id、severity、pattern、view）。
- [ ] 修改某条规则的 severity 后，历史判定的 severity **不变**（ADR 0003）。
- [ ] 因此永久禁言的判定门槛不受语料库后续变更影响。断言：改掉规则 severity 后，同一玩家的 7 天计数与是否会触发永久禁言，与改动前一致。
- [ ] 软删除玩家后，其历史判定仍可查询。

## 4. 界面

单页，三个区域（布局属于实现细节，功能集合不是）：

1. **玩家区**：当前玩家选择器（可切换）、输入框、发送按钮、我的禁言状态与倒计时。
2. **管理员 · 全局流**：所有玩家的消息与判定，逐条含命中规则、等级、处置、时长；被拒绝的消息也在这里出现并标明原因。
3. **管理员 · 语料库**：
   - 规则与映射列表（可手工增删改）
   - "使用 agent 变更语料库"：输入自然语言要求 + 可选"附带最近 30 条消息样本"
   - 草案审批区：逐条勾选 / 编辑 / 校验状态 / 提交
   - 修订列表与回滚
   - 试跑面板
   - 只读展示当前阶梯

- [ ] 页面上没有任何需要刷新才能看到的变化：判定、禁言生效、禁言到期、语料库提交全部实时反映。

## 6. 端到端场景（人工验收脚本）

1. 建玩家 `alice`、`bob`。
2. 以 `alice` 发一条命中 L1 规则的消息 → 判定 L1，禁言 1min，alice 端立刻看到倒计时。
3. 禁言期间 alice 再发 → 被拒绝，bob 仍能正常发言（全局流里两条都在）。
4. 管理员提前解除 alice 的禁言（不填原因 → 被拒；填了 → 生效），alice 立刻能发言。
5. 让 alice 在 7 天内累计到第 3 次违规 → 断言被禁 1d（不是 1min）。
6. alice 终身累到第 5 次 → 断言永久禁言，且倒计时区显示"永久"。
7. 用 agent 生成一条藏头规则草案（`view = acrostic`，pattern 为某句脏话）→ 校验通过 → 提交。
8. 以 bob 发一条三行藏头消息 → 断言被判违规，且界面能展示抽取出的那列首字。
9. 在试跑面板贴入一段正常聊天 + 一段广告 → 断言只命中广告那条，且不产生任何判定记录。
10. 把 alice 软删除 → 列表消失；用同名重建 → 新 alice 的 7 天与终身计数均为 0，旧判定仍可查。
11. 回滚语料库到上一条修订 → 提交需要的第 8 步那条藏头消息不再被判违规。
