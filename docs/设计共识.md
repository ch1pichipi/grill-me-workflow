# 设计共识

这份文档是一次设计访谈的结论存档。它不重复论证过程，只记录**已经定下的**内容；每条细节的"为什么"见 `docs/技术选型.md`，少数难以逆转的决定见 `docs/adr/`。

## 一中段话概括

一个单机运行的聊天审核演示系统：玩家在网页里发消息，服务端用"归一化 + 视图 + 关键词/正则"的管线判断违规等级，再结合近 7 天与终身的违规次数决定禁言档位；管理员可以提前解除禁言、可以切换玩家身份、可以用 agent 提出语料库变更草案并逐条审批，也可以在不提交的情况下用草稿语料库试跑一段文本。

---

## 1. 交付形态

单机演示项目。`go run .` 起一个进程，浏览器打开就是全部界面。

- 无登录、无鉴权、无多实例。
- 管理员视图与玩家视图在同一个页面里切换。
- 前端是单个 `index.html` + 原生 JS，用 `go:embed` 打进二进制，无构建步骤。

## 2. 领域语言

正式术语见 `GLOSSARY.md`。要点：**禁言**（不是"封禁"）、**判定**（不是"结果"）、**处置档位**（不是"惩罚等级"）、**语料库**（不是"敏感词表"）、**视图**、**修订**、**变更草案**。

`初步需求文档.md` 已同步用词，并在开头指向 `GLOSSARY.md`。

## 3. 技术栈

- Go；`cmd/` 入口，`internal/` 按能力切深模块：`corpus` / `moderation` / `punishment` / `store` / `httpapi`。
- `modernc.org/sqlite`（纯 Go，无 CGO）、Go 1.22 标准库路由、`coder/websocket`。
- WebSocket 是唯一通道：发消息、审核结果、禁言生效与解除、全局消息流全部走它。
- SQLite 全量落盘；单文件 `schema.sql`，启动时 `CREATE TABLE IF NOT EXISTS`，不做迁移。
- LLM：`Drafter` 接口 + OpenAI 兼容中转站实现（`opencode-go` / `deepseek-v4.1-flash`）+ fake 实现供测试。

## 4. 审核管线

`原文 → 归一化 → 视图 → literal | regex`

- 归一化映射属于语料库，按 `from` 长度降序应用，等长按 id。
- 两个视图：`raw`（归一化后的文本本身）、`acrostic`（按换行 + 中文标点切句，取每段首个非空白字符）。
- 两种匹配器：`literal`、`regex`。没有第三种。
- 规则字段：`id / 说明 / view / matcher / pattern / severity(1–5) / enabled / examples`。
- 语料库在内存中编译为快照（关键词索引 + 已编译正则），由 `atomic.Pointer` 持有；提交修订后重建并原子替换。

## 5. 等级

违规等级 = 命中规则的**最高** severity；同一条消息命中**不同**规则 ≥ 2 条时 +1，封顶 5。累积值（命中条数）只作人工复核信号，不参与自动处置。→ ADR 0001

## 6. 违规历史与处置

- 计数对象：**违规消息条数**，一条消息算 1 次，与命中几条规则无关。
- 两个计数：滚动 7 天、终身。7 天计数**每次现算**（查判定表），不存冗余计数列。
- 禁言期间被拦截的消息**不计入**违规历史。
- 档位：`rung = clamp(severity + 7天计数 - 2, 0, 3)` → 时长 `[1min, 1h, 1d, 3d]`。
- 永久禁言：**终身计数 ≥ 5** 时独立触发，优先级高于档位公式。
- 阶梯是 `punishment` 包内的常量，前端只读展示（数据从后端读）。

## 7. 禁言状态机

- 每个玩家最多一条活跃禁言。
- 新判定到来时替换为更严格者：`max(剩余时间, 新时长)`，并在判定流里记录"被替换"。
- 到期为惰性判定（读状态时比较 `now > expiresAt`），并在到期时刻主动推送"你可以说话了"。
- 提前解除：**原因必填**，操作人固定为 `admin`。

## 8. 语料库、草案、修订

- agent 只产出**变更草案**，永不写库 → ADR 0002。
- 草案 = 结构化操作列表 `{op, target, before, after, reason}`；可逐条勾选、逐条编辑 `after`、**部分提交**。
- 校验：severity 在 1–5、正则必须编译通过、映射不得为空、id 不得冲突、**规则必须命中自己的 examples**。失败项标红且不可勾选，其余照常提交。
- 提交即一次**修订**：操作列表 + 提交后的完整语料库快照。回滚 = 把历史快照作为**新的一次修订**提交。
- agent 默认看不到聊天内容；勾选"附带最近消息样本"后附带最近 **30** 条消息及其判定，草案标注"基于哪几条样本"。
- 试跑面板：用**草稿状态**的语料库跑一段文本，显示命中规则、等级、档位、会施加的时长；不写库、不产生判定。

## 9. 留存

判定记录：消息原文（截断 2000 字）+ 归一化后文本 + 命中规则快照（id、当时的 severity、pattern、view）→ ADR 0003。

## 10. 玩家

- 内部自增 id + 名字；名字可改，按 id 切换。
- 管理员可增删玩家；删除为**软删除**，历史与判定全部保留，同名可重建为新玩家。
- 玩家列表显示：名字 / 当前禁言剩余 / 7 天违规次数 / 终身违规次数。

## 11. 测试

`moderation`、`punishment`、语料库校验做表驱动测试；外加**一条**端到端冒烟测试（起进程 → 连 WS → 发违规消息 → 断言禁言事件与到期时间）。
