# 密钥管理：吊销、注入与历史清理

> 结论先写前面：**吊销重发是必须动作，改代码/删历史都不能替代吊销**。
> 旧 key 一旦进过 Git 历史（哪怕是私有仓库），就当作已泄露。

## 0. 立即吊销（只有你能做）

1. 打开 key 所属的中转站控制台，找到 `oc_sk_...` 这个 key，**吊销/删除**。
2. 新建一个 key，只复制到下面两个地方：
   - 本机 pi 配置 `C:\Users\xuzongqi\.pi\agent\models.json`（该文件不在本仓库）
   - 当前进程的环境变量 `AGENT_API_KEY`（见下一节）
3. 如果仓库曾经公开过、或被 fork/克隆过，假设旧 key 已经被拿走；
   清理历史后再轮换一次也不为过。

## 1. 用环境变量注入，而不是写进代码

服务端只从 `AGENT_API_KEY` 读取 key，没有内置默认值；未注入时 agent 自动禁用，
其余功能完全可用。

Windows PowerShell（推荐用脚本从 models.json 读，key 不进仓库、不落盘）：

```powershell
.\scripts\run-with-agent.ps1
```

或者手工注入：

```powershell
$env:AGENT_API_KEY = "新的 key"
$env:AGENT_BASE_URL = "https://opencode.ai/zen/go/v1"   # 可选
$env:AGENT_MODEL = "deepseek-v4.1-flash"                # 可选
go run .
```

> `scripts/run-with-agent.ps1` 只是在启动 `go run .` 前把 key 放进当前进程环境，
> 进程退出后 `finally` 会删掉环境变量；它不会打印 key，也不会写任何文件。

其他环境（CI、容器、systemd）同样用环境变量或 secret store 注入，不要把 key 写进
Dockerfile、docker-compose.yml、CI 配置文件或 `.env` 后提交。

## 2. 清理 Git 历史

> 先吊销，再清理。清理只能减少后续泄露面，不能让已经泄露的 key 变安全。

### 方案 A：git-filter-repo（推荐）

```bash
pip install git-filter-repo

# 把旧 key 写进一个临时文件（不提交、完成后删除）。
# 不要把完整 key 写进本文档或任何提交里。
read -rsp "旧 key（oc_sk_ 开头的那串）: " OLD_KEY; echo
printf '%s==>REMOVED_REVOKED_KEY\n' "$OLD_KEY" > /tmp/chatmod-secrets.txt
unset OLD_KEY

git filter-repo --replace-text /tmp/chatmod-secrets.txt --force
rm -f /tmp/chatmod-secrets.txt
```

### 方案 B：BFG Repo-Cleaner

```bash
java -jar bfg.jar --replace-text /tmp/chatmod-secrets.txt .git
git reflog expire --expire=now --all
git gc --prune=now --aggressive
```

### 推送到远端（破坏性操作）

**必须通知所有协作者**：重写后旧提交哈希全部改变，其他人需要重新 clone，
不要直接 pull。

```bash
git push --force --all
git push --force --tags
```

如果远端开了分支保护，先临时放开，推完再恢复。

## 3. 验证

```bash
# 所有分支/标签的历史里都不应再出现
git log --all -S 'oc_sk_' --oneline
git grep -I 'oc_sk_' $(git rev-list --all) -- . 2>/dev/null | head

# 工作区与未跟踪文件
git grep -I 'oc_sk_'
```

另外建议在仓库/CI 上开启 secret scanning（GitHub Secret Scanning、gitleaks、
trufflehog 任一），防止下一次再提交进来。

## 4. 本项目的硬性约定

- `AGENT_API_KEY` **没有默认值**；`internal/drafter` 不再包含任何 key 常量。
- 未配置 key 时服务正常启动，agent 按钮禁用并提示手工编辑语料库。
- 任何日志都不打印 `Authorization` 头；agent 往返日志只记录请求体与响应体。
- key 只存在于进程环境或本机未入库的配置文件里。
